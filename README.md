# @sendrin/sdk (Node SDK)

Official Node.js/TypeScript SDK for the Sendrin notification API.

## Install

```bash
npm install @sendrin/sdk
```

## Quickstart

```ts
import { Sendrin } from "@sendrin/sdk";

const client = new Sendrin("gns_live_sk_9d8f7e6a5b4c3d2e1f0a");

const sent = await client.otp.send({
  channel: "sms",
  recipient_phone: "+14155552671",
  purpose: "login",
});
console.log("Sent:", sent.otp_id);

// Prompt your user for the code they received, then verify it.
const result = await client.otp.verify({
  channel: "sms",
  code: "123456",
  recipient_phone: "+14155552671",
  purpose: "login",
});
console.log("Verified:", result.verified);
```

## The `Sendrin` client

```ts
import { Sendrin } from "@sendrin/sdk";

const client = new Sendrin("gns_live_sk_...", {
  baseUrl: "https://api.sendrin.com", // default shown
  timeoutMs: 10_000,                  // default shown
  maxRetries: 2,                      // default shown
});
```

- First argument — your Sendrin application secret key. Sent as
  `Authorization: Bearer <apiKey>`.
- `baseUrl` — override to point at a different environment.
- `timeoutMs` — per-request timeout, enforced via `AbortController`.
- `maxRetries` — number of retries for network errors and `5xx` responses,
  with exponential backoff (500ms, 1000ms, 2000ms, ...). `429` responses are
  never retried — they raise `SendrinQuotaExceededError` immediately, since
  retrying a quota error immediately just burns another request against the
  same quota.

### OTP

```ts
await client.otp.send({
  channel: "sms", // or "email"
  recipient_phone: "+14155552671",
  purpose: "login",
  // code_length, ttl_seconds, brand_name, application_id, support_email,
  // code, recipient_email are all optional — fields you don't pass are
  // omitted from the request so the server applies its own defaults.
});

await client.otp.verify({
  channel: "sms",
  code: "123456",
  recipient_phone: "+14155552671",
  purpose: "login",
});
```

Errors raise `SendrinAPIError` (with `.statusCode` and `.errorCode`) or its
subclass `SendrinQuotaExceededError` for `429` responses.

## Webhook signature verification

```ts
import { verifyWebhook, WebhookVerificationError } from "@sendrin/sdk";

try {
  verifyWebhook({
    body: rawRequestBody, // Buffer — see warning below
    timestamp: req.headers["x-gns-timestamp"] as string,
    signature: req.headers["x-gns-signature"] as string,
    secret: "whsec_...",
    toleranceSeconds: 300, // default shown
  });
} catch (err) {
  if (err instanceof WebhookVerificationError) {
    // reject the webhook
  }
  throw err;
}
```

> [!WARNING]
> `body` **must** be the raw request body bytes exactly as received — do not
> `JSON.parse` and re-stringify it before calling `verifyWebhook`. Sendrin
> signs the exact bytes it transmits; re-serializing risks a whitespace or
> key-order mismatch that would make even a genuine, untampered webhook fail
> verification. In an Express app, this means using a raw-body parser (e.g.
> `express.raw({ type: "application/json" })`) on the webhook route instead
> of the default JSON body parser.

`verifyWebhook` throws `WebhookVerificationError` if the signature is
invalid, the signature format is unrecognized, or the timestamp is outside
`toleranceSeconds` of the current time (replay-attack protection).

## Exports

`@sendrin/sdk`'s public surface (`src/index.ts`):

- `Sendrin`, `SendrinOptions` — the client and its constructor options.
- `SendOtpInput`, `VerifyOtpInput` — input types for `client.otp.send` / `client.otp.verify`.
- `SendrinAPIError`, `SendrinQuotaExceededError` — error classes.
- `verifyWebhook`, `VerifyWebhookOptions`, `WebhookVerificationError` — webhook verification.

## Development

Install dependencies from the monorepo root, then from this package:

```bash
npm install
```

Run tests:

```bash
npx vitest run
```

Lint:

```bash
npm run lint
```

Build:

```bash
npm run build
```

### Regenerating types

`src/generated/openapi-types.ts` is generated by
[`openapi-typescript`](https://github.com/openapi-ts/openapi-typescript) from
Sendrin's OpenAPI spec and is committed to the repository — do not hand-edit
it. To regenerate after the spec changes:

```bash
npm run generate-types
```
